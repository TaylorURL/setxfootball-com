# SETX Football

Registration and shirt orders for a youth football camp in Daisetta, Texas.

[setxfootball.org](https://www.setxfootball.org)

<img src="https://img.shields.io/badge/version-2026.44.3-e11d2a?style=for-the-badge" alt="Version 2026.44.3" />

A free camp for kids 5 to 12, two half-days in July. The only cost is $5 per camp shirt. Parents sign kids up and order shirts from their phone, no account needed. Volunteers get a staff panel for payments and the roster.

<details>
<summary>What's on the site</summary>

- Camp, coach, photo, sponsor and contact pages.
- A sign-up form with one entry per camper, a shirt size each and a running total. Payment is by CashApp after.
- A parent dashboard to check payment status and edit a sign-up for 3 days after it's filed.
- A staff panel to search the roster, group families, mark payments paid and export CSV.

</details>

## How it's built

- **Access rules live in Postgres.** The browser only has the publishable key, so row level security is the boundary, not the UI.
- **Signed-out visitors can file and read nothing.** Anon has an insert policy and no select grant. The client mints the row id itself, so the insert never needs to read anything back.
- **Families can't mark themselves paid.** A policy's `WITH CHECK` only sees the new row, so it can't tell whether `payment_status` moved. A trigger compares old and new and blocks family writes to the staff and system columns.
- **The 3-day edit window is enforced in the database.** The dashboard hides Edit after 3 days, and the update path refuses it too. `created_at` is frozen, since the window is measured from it.
- **The staff check reads the session once per statement.** `is_camp_staff()` gets inlined by the planner, so the `auth.uid()` hoist has to be inside the function, not only around it.

<details>
<summary>Front-end performance</summary>

Create React App with a `postbuild` chain:

- `prerender.js` writes each public route's first screen into its own HTML. `/auth`, `/dashboard`, `/staff` and `/payment` get the empty shell, since they depend on a session. Unmatched paths go to `404.html`.
- `drop-remote-font-import.js` removes the design system's Google Fonts `@import`. Geist is served from two local subset files instead, the first preloaded.
- `preload-hero-image.js` puts the hero photo in the head as a preload with the same srcset and sizes the img uses.
- `preload-shared-chunks.js` preloads the one chunk every route needs, so it starts with `main.js` instead of a round trip later.
- `start-bundle-after-hero.js` holds the bundle until the hero photo is painted, so it isn't competing with the largest paint for bandwidth.
- AVIF copies of every photo are generated by hand (`npm run images:avif`) and committed next to the WebP.

</details>

<details>
<summary>Running it locally</summary>

```bash
npm install
cp .env.example .env
npm start
```

Fill in `REACT_APP_SUPABASE_URL` and `REACT_APP_SUPABASE_ANON_KEY` in `.env`. The dev server runs at http://localhost:3000. The marketing pages load without them, but sign-up and sign-in need a Supabase project.

Other scripts: `npm run build`, `npm test`, `npm run lint` and `npm run format`.

</details>
